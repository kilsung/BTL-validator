📌 Summary (요구사항 요약)

시스템은 공통 Gateway 설정(gateway.json)과 하나 이상의 장치 프로필(conf/profiles/*.json)을 로드하고, 필수 필드 누락, Modbus 주소 범위, 객체 식별자(instance) 중복, 데이터 타입 및 지원 값을 엄격히 검증한다. 프로필 검증 실패 시 외부 서비스를 시작하지 않고 진단 오류 로그와 함께 Crash Loop 방지를 위해 ConfigHold(60초 재검증 대기) 상태로 진입한다. (단, gateway.json 공통 설정 자체의 실패는 즉시 종료)

🔄 Input / Output Relationship (입출력 관계)

- 입력 (Input): 설정 디렉터리 경로(conf/), gateway.json(Device ID, 포트, 시리얼 파라미터), profiles/*.json(객체 목록, full_address/offset_address, data_type, scale, offset 등)

- 출력 (Output): 파싱된 GatewayConfig 및 DeviceProfile 객체 메모리 트리, 또는 오류 발생 시 상세 진단 에러 로그(FATAL CONFIG ERROR: <file>:<object> - <reason>) 및 ConfigHold 상태 진입

- 데이터 변환: 5/6자리 full_address를 표준 Modbus 블록(0x/1x/3x/4x) 및 0-based 오프셋 주소로 자동 분기 변환

⚡ Normal / Alternative Flow (정상 / 대안 동작)

- 정상 흐름 (Normal Flow):

1. main() 진입 후 ConfigLoader::load_gateway_config()를 호출하여 gateway.json을 읽고 유효성을 검증한다.

2. ConfigLoader::load_device_profiles()를 호출하여 profiles/ 디렉터리 내 모든 JSON 파일을 순회 로드한다.

3. 각 프로필의 필수 필드(objects 배열, 주소 유효성 등)와 인스턴스 중복 여부를 전수 검사한다.

4. 전체 검증 통과 시 success=true와 함께 객체 매핑 테이블(ObjectMapping 목록)을 확정하고 다음 기동 단계로 진행한다.

- 대안 흐름 (Alternative Flow): 프로필 파일 누락, JSON 문법 오류, 필수 주소 누락, 지원되지 않는 데이터 타입 검출 시 즉시 오류 로그를 출력한 뒤 외부 서비스를 개시하지 않고 ConfigHold 상태로 진입하여 60초 후 재검증을 수행한다.

🛡️ 부가요소 (예외/제약/품질/연관관계)

- Exception Handling (예외처리):

프로필 내 JSON 파싱 에러, 필수 키 누락, 주소 범위(0~65535 초과) 오류 발생 시 외부 통신을 차단하고 60초 주기 ConfigHold 상태로 진입하여 Crash Loop를 방지하고 설정 수정을 대기한다. (루트 공통 설정인 gateway.json 누락/오류는 즉시 exit(1) 종료)

- Constrain (제약사항):

프로필 로드는 원자적(Atomic)으로 수행되어야 하며, 파싱 중 일부 파일만 성공하더라도 전체가 통과하지 않으면 메모리에 부분 객체를 남기지 않는다.

- Quality Requirement (품질 요구사항):

설정 검증 완료 시간 <= 1.0초, 진단 로그에 파일명과 오류 위치를 명확히 출력한다.

- Relation with other Requirement (다른 요구사항과의 연관관계):

SRS-FUN-CFG-002 Min/Max 모순 및 설정 오류 홀드
🔴 Managed 전용 (시뮬레이션/장애주입) 3 Test Cases
📌 Summary (요구사항 요약)

프로필 객체에 min_value와 max_value가 모두 존재하고 min_value > max_value인 경우를 포함하여 모든 프로필 검증 실패 시, 시스템은 프로세스를 비정상 종료하는 대신 '설정 오류 홀드(Config Hold)' 상태로 진입하여 60초마다 파일 수정을 감시 및 자동 재검증한다. 설정이 복구되면 무중단으로 정상 기동을 재개한다.

🔄 Input / Output Relationship (입출력 관계)

- 입력 (Input): 프로필 내 min_value, max_value 설정 파라미터 (Double 타입)

- 출력 (Output): 모순 검출 시 FATAL CONFIG ERROR: min_value > max_value 진단 로그 출력, is_contradiction=true 플래그 반환, 60초 타이머 상태 진입

- 상태 전이: LoadProfiles -> ConfigHold (60초 주기 재검증 루프) -> 파일 복구 시 WaitModbus로 전이

⚡ Normal / Alternative Flow (정상 / 대안 동작)

- 정상 흐름 (Normal Flow):

1. 프로필 로드 중 min_value > max_value 모순을 검출한다.

2. ConfigLoader는 is_contradiction=true와 함께 실패한 파일, 객체, Min, Max 상세 정보를 반환한다.

3. Lifecycle 관리자는 눈에 띄는 치명적 오류 안내와 60초 재검증 카운트다운 로그를 출력하고 홀드 루프로 진입한다.

4. 60초 후(또는 Inotify 파일 변경 감지 시) 전체 프로필을 원자적으로 재검증한다.

5. 파일이 정상 수정되면 프로세스 재시작 없이 즉시 Modbus/BACnet 초기화 흐름으로 복귀한다.

- 대안 흐름 (Alternative Flow): 60초 후 재검증에서도 모순이 유지되면 홀드 상태를 유지하며 60초 대기를 반복한다.

🛡️ 부가요소 (예외/제약/품질/연관관계)

- Additional Flow (부가동작):

홀드 루프 중 Inotify 이벤트 또는 60초 주기 타이머로 profiles/ 변경을 감시한다.

- Exception Handling (예외처리):

systemd/Supervisor에 의한 무한 Crash Loop(빠른 재시작 반복으로 인한 시스템 자원 고갈)를 방지하기 위해 프로세스 생존을 유지한다.

- Constrain (제약사항):

홀드 중에는 외부 Modbus 요청 송신이나 BACnet UDP 소켓 바인딩을 일체 개시하지 않는다.

- Quality Requirement (품질 요구사항):
