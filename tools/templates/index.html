FD (Foreign Device) 검증 환경 (ASHRAE 135-2020 Annex J.5)

FD(Foreign Device)란?

BACnet/IP 장치(DUT)가 서로 다른 서브넷의 BBMD(Broadcast Management Device)에 Register-Foreign-Device 요청을 전송하고 등록됨으로써, 서브넷 경계를 넘어 BACnet 브로드캐스트를 수신할 수 있게 되는 기능입니다. (ASHRAE 135 Annex J.5)

검증 방법:

  1. DUT(bacstac_rt.conf): Foreign_Device=1, Fd_Bbmd_Ip=검증PC_IP 설정
  2. 검증 툴이 포트 47809에서 수신 대기 (임시 BBMD 역할)
  3. DUT가 자동으로 Register-FD 전송 → 검증 툴이 BVLC-Result(Success) 응답
  4. 등록 완료 후 WhoIs/I-Am 교환으로 BACnet 통신 검증
  5. WireShark로 캡처된 패킷 상세가 결과 영역에 표시됨

검증 항목:

ID항목표준 조항Pass 기준
FD-01 FD-Register-Recv Annex J.5 Register-FD 수신 + Success 응답
FD-02 WhoIs-I-Am §20.1.2 / Annex J I-Am 응답 수신
DUT 설정 (bacstac_rt.conf)
Bip*Bbmd: 0
Bip*Foreign_Device: 1
Bip*Fd_Bbmd_Ip: "검증PC_IP"
Bip*Fd_Bbmd_Udp: 0x0000BAC1
(47809: FD 전용) Bip*Fd_Time_To_Live: 0x00000E10
FD 검증 설정
DUT 사전 설정 (1회)
bacstac_rt.conf 에서:
 • Foreign_Device = 1
 • Fd_Bbmd_Ip = <이 검증 PC의 IP>
 • Fd_Bbmd_Udp = 0x0000BAC1 (47809)
DUT 포트 47808(일반 BACnet) · 47809(FD 등록) 동시 운영 — 검증 중에도 BACnet 정상 동작
DUT 재시도 주기(~30초)보다 크게 설정하세요.
① 포트 47809 수신 대기 → ② DUT Register-FD 자동 수신 → ③ WhoIs/I-Am 검증
ⓘ 일반 BACnet(47808)은 동시에 동작 가능
재검증 주의: FD 등록 성공 후 DUT는 TTL(3600초) 만료 전까지 재등록하지 않습니다.
재검증이 필요하면 DUT 서비스를 재시작하세요:

BBMD(BACnet/IP Broadcast Management Device)란?

서로 다른 IP 서브넷 간에 BACnet 브로드캐스트를 라우팅하는 장치입니다. BACnet/IP 환경에서 다중 서브넷 운용 시 필수 기능입니다.

검증 전 준비:

  1. 검증 툴 PC와 BBMD 장치가 같은 IP 서브넷에 있어야 합니다.
  2. UDP 포트 47808이 방화벽에서 허용되어야 합니다.
  3. BACnet 연결 없이 독립 실행 가능합니다.

테스트 항목:

ID테스트표준 조항Pass 기준
BBMD-01Read-BDTAnnex J.4Read-BDT-Ack 수신
BBMD-02Register-FDAnnex J.5BVLC-Result(Success) 수신
BBMD-03Read-FDTAnnex J.6Read-FDT-Ack 수신
BBMD-04Delete-FDT-EntryAnnex J.7BVLC-Result(Success) 수신
BBMD-05WhoIs via BBMDAnnex J.9I-Am 응답 수신

검증 PC 설정

Windows / Linux 공통

IP: 192.168.1.10

sudo ufw allow 47808/udp

DUT (ACPi) 설정

BACnet 설정 파일

IP: 192.168.1.100
서브넷마스크: 255.255.255.0
BACnet UDP 포트: 47808
BBMD 기능: 활성화

BDT (Broadcast Distribution Table) 설정:

# 단일 서브넷 테스트 시:
BDT[0]: 192.168.1.255
       /255.255.255.0
       :47808

# 다중 서브넷 시 추가:
BDT[1]: 192.168.2.100
       /255.255.255.0
       :47808
BDT는 최소 자기 자신의 서브넷 브로드캐스트 주소 포함

1. Ping 테스트:

# Linux
sudo ss -ulnp | grep 47808

# Wireshark 필터:
udp.port == 47808

3. BBMD 지원 빠른 확인:

위 "BBMD 지원 여부 빠른 확인"
버튼으로 Read-BDT 응답 확인

자주 발생하는 문제와 해결 방법

BBMD-01 Timeout
  • DUT IP 주소 재확인
  • 방화벽 UDP 47808 차단 여부 확인
  • BBMD 기능 활성화 여부 확인
  • 같은 서브넷인지 확인 (ping 테스트)
BBMD-02 BVLC-Result(NAK)
  • DUT가 FD 등록을 허용하는지 확인
  • FDT 용량 초과 여부 확인
  • TTL 값이 너무 짧지 않은지 (최소 10초)
BBMD-05 I-Am 미수신
  • DUT가 BACnet 서버로도 동작 중인지 확인
  • DUT의 Device Instance 번호 확인
  • WhoIs 범위 설정 확인 (0~4194302)

근본 원인 분석

config.c: bacBipCfg.bbmd = NULL
BACstac subdlbip.c 361줄:
pContext->fBbmd = (bip->bbmd != NULL)
→ fBbmd = FALSE → BBMD 완전 비활성화
bacBipBbmdCfg.maxFdtEntries = 0
FDT 크기 0 → Register-FD 요청 시 NAK 응답
BBMD-02/03/04 테스트 전부 실패
선언 순서 오류
bacBipBbmdCfg가 bacBipCfg 뒤에 정의 →
&bacBipBbmdCfg 참조 불가 구조

수정 내용 (config.c)

/* 수정 전 */
- NULL /* BBMD 비활성화 */
- 0, /* maxFdtEntries */

/* 수정 후 */
+ BBMD cfg 를 bacBipCfg 앞으로 이동
+ &bacBipBbmdCfg /* BBMD 활성화 */
+ 10, /* maxFdtEntries: FD 등록 허용 */
수정 후 기대 동작:
✓ Read-BDT → Read-BDT-Ack 응답
✓ Register-FD → BVLC-Result(0x0000) Success
✓ Read-FDT → Read-FDT-Ack (등록 항목 포함)
✓ Delete-FDT → BVLC-Result Success
✓ WhoIs via BBMD → I-Am 응답
